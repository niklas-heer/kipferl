Kipferl is available for macOS and Linux. **v0.7.0-rc.1 is a published release
candidate** with project templates, local-module bundling, and compatibility-checked
PyPI packages. Use it to follow the current application tutorials and test your
apps before stable 0.7. **v0.6.0 remains the stable and Homebrew release.**

## Release candidate

Download [v0.7.0-rc.1](https://github.com/niklas-heer/kipferl/releases/tag/v0.7.0-rc.1)
for your operating system and CPU:

| Platform | Release-candidate binary | Checksum |
| --- | --- | --- |
| macOS Apple Silicon | [kipferl-macos-aarch64](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-macos-aarch64) | [SHA-256](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-macos-aarch64.sha256) |
| macOS Intel | [kipferl-macos-x86_64](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-macos-x86_64) | [SHA-256](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-macos-x86_64.sha256) |
| Linux x86_64 | [kipferl-linux-x86_64](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-linux-x86_64) | [SHA-256](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-linux-x86_64.sha256) |
| Linux ARM64 | [kipferl-linux-aarch64](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-linux-aarch64) | [SHA-256](https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1/kipferl-linux-aarch64.sha256) |

Choose `asset` from the table before running these commands. This installs into
a new directory and leaves your stable executable available for rollback:

```bash
asset=kipferl-macos-aarch64
release=https://github.com/niklas-heer/kipferl/releases/download/v0.7.0-rc.1
rc_dir=$(mktemp -d "$HOME/kipferl-0.7.0-rc.1.XXXXXX")
cd "$rc_dir"
curl -fLO "$release/$asset"
curl -fLO "$release/$asset.sha256"
```

Verify the checksum with the command for your operating system:

```bash
# macOS:
shasum -a 256 -c "$asset.sha256"
# Linux:
sha256sum -c "$asset.sha256"
```

Continue only when verification reports `OK`. Keep the downloaded files under
their original names until verification succeeds. Then:

```bash
chmod +x "$asset"
mv "$asset" kipferl
./kipferl --version
export PATH="$rc_dir:$PATH"
kipferl new --help
```

The version should be `Kipferl v0.7.0-rc.1`. The `PATH` change applies to this
shell; opening a fresh shell restores your previous selection. Before upgrading
a project, read the [import and dependency-lock changes](/docs/guides/packages#upgrade-to-070-rc1).

## Stable Homebrew

Install stable v0.6.0 on macOS or Linux. Homebrew does not select the release candidate:

```bash
brew install niklas-heer/tap/kipferl
```

Existing Kipferl users can update with `brew upgrade kipferl`.

If the old μcharm 0.5 Homebrew formula is installed, replace it once. Kipferl
0.6 keeps the old command as a deprecated alias, so existing scripts continue
to work during the transition:

```bash
brew uninstall --force ucharm
brew install niklas-heer/tap/kipferl
```

## Stable direct download

Choose the release asset for the machine running Kipferl:

| Platform | Asset |
| --- | --- |
| macOS Apple Silicon | `kipferl-macos-aarch64` |
| macOS Intel | `kipferl-macos-x86_64` |
| Linux x86_64 | `kipferl-linux-x86_64` |
| Linux ARM64 | `kipferl-linux-aarch64` |

Download both files **with their original names** so checksum verification
matches the filename inside the `.sha256` file. For example, on Apple Silicon:

```bash
asset=kipferl-macos-aarch64
release=https://github.com/niklas-heer/kipferl/releases/download/v0.6.0
curl -fLO "$release/$asset"
curl -fLO "$release/$asset.sha256"
shasum -a 256 -c "$asset.sha256"
# On Linux, use: sha256sum -c "$asset.sha256"
chmod +x "$asset"
mkdir -p "$HOME/.local/bin"
mv "$asset" "$HOME/.local/bin/kipferl"
export PATH="$HOME/.local/bin:$PATH"
kipferl --version
```

Choose the correct `asset` before running the commands. Verify the checksum
successfully before installing the binary. Add `~/.local/bin` to your shell's
`PATH` permanently if it is not already there.

## Development checkout

To change Kipferl itself or try changes after the release candidate, install the
source checkout with the repository's pinned mise setup. This requires Git,
mise 2026.9.1 or newer, and a native C compiler/linker. On macOS, use the Xcode Command Line Tools.

```bash
git clone https://github.com/niklas-heer/kipferl.git
cd kipferl
mise trust
mise install --locked rust python node bun cargo:bacon aqua:nextest-rs/nextest/cargo-nextest watchexec
mise run setup
mise run install
export PATH="$HOME/.local/bin:$PATH"
kipferl new --help
```

`mise run install` links this checkout's CLI into `~/.local/bin`. Review task
definitions before trusting them. See [Developing Kipferl](/docs/guides/development)
for tool pins, tests, website tasks, and the distinction between newly compiled
runtime code and the CLI's embedded prebuilt components.

If `--template` is absent from `kipferl new --help`, your shell is still finding
an older CLI. Check `command -v kipferl` and select the release candidate or put
the development symlink first on `PATH`. Source builds can share a version label
while embedding different runtime bytes; package locks also check that identity.

## Verify Installation

```bash
kipferl --version
```

Stable installations show:

```
Kipferl v0.6.0
```

## Editor setup

With v0.7.0-rc.1, new projects include autocomplete stubs and Pyright configuration:

```bash
kipferl new my-cli --template cli
cd my_cli
```

For an existing project, run `kipferl init` to add editor stubs. Use
`kipferl init --help` for optional AI-tool instructions and editor integrations.
See [project commands](/docs/commands/projects) to enable shell completion.
