Kipferl is available for macOS and Linux. Choose the published stable binary
or build the current source checkout. The project templates, local-module
bundling, and contributor workflow in these docs include unreleased changes;
use the development checkout to follow those examples.

## Homebrew

Install the stable release on macOS or Linux:

```bash
brew install niklas-heer/tap/kipferl
```

Existing Kipferl users can update with `brew upgrade kipferl`.

If the old μcharm 0.5 Homebrew formula is installed, replace it once. Kipferl
0.6 keeps the old command as a deprecated alias, so existing scripts continue
to work during the transition:

```bash
brew uninstall --force ucharm
brew install niklas-heer/tap/kipferl
```

## Direct download

Choose the release asset for the machine running Kipferl:

| Platform | Asset |
| --- | --- |
| macOS Apple Silicon | `kipferl-macos-aarch64` |
| macOS Intel | `kipferl-macos-x86_64` |
| Linux x86_64 | `kipferl-linux-x86_64` |
| Linux ARM64 | `kipferl-linux-aarch64` |

Download both files **with their original names** so checksum verification
matches the filename inside the `.sha256` file. For example, on Apple Silicon:

```bash
asset=kipferl-macos-aarch64
release=https://github.com/niklas-heer/kipferl/releases/download/v0.6.0
curl -fLO "$release/$asset"
curl -fLO "$release/$asset.sha256"
shasum -a 256 -c "$asset.sha256"
# On Linux, use: sha256sum -c "$asset.sha256"
chmod +x "$asset"
mkdir -p "$HOME/.local/bin"
mv "$asset" "$HOME/.local/bin/kipferl"
export PATH="$HOME/.local/bin:$PATH"
kipferl --version
```

Choose the correct `asset` before running the commands. Verify the checksum
successfully before installing the binary. Add `~/.local/bin` to your shell's
`PATH` permanently if it is not already there.

## Development checkout

To use the current project workflow, install the source checkout with the
repository's pinned mise setup. This requires Git, mise 2026.9.1 or newer, and a
native C compiler/linker. On macOS, use the Xcode Command Line Tools.

```bash
git clone https://github.com/niklas-heer/kipferl.git
cd kipferl
mise trust
mise install --locked rust python node bun cargo:bacon aqua:nextest-rs/nextest/cargo-nextest watchexec
mise run setup
mise run install
export PATH="$HOME/.local/bin:$PATH"
kipferl new --help
```

`mise run install` links this checkout's CLI into `~/.local/bin`. Review task
definitions before trusting them. See [Developing Kipferl](/docs/guides/development)
for tool pins, tests, website tasks, and the distinction between newly compiled
runtime code and the CLI's embedded prebuilt components.

If `--template` is absent from `kipferl new --help`, your shell is still finding
an older CLI. Check `command -v kipferl` and put the development symlink first
on `PATH`. The checkout can retain the same version label as the published
release, so `--version` alone does not identify the new command surface.

## Verify Installation

```bash
kipferl --version
```

You should see output like:

```
Kipferl v0.6.0
```

## Editor setup

New projects include autocomplete stubs and Pyright configuration:

```bash
kipferl new my-cli --template cli
cd my_cli
```

For an existing project, run `kipferl init` to add editor stubs. Use
`kipferl init --help` for optional AI-tool instructions and editor integrations.
See [project commands](/docs/commands/projects) to enable shell completion.
